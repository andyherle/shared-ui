# Shared UI

One repository, two packs: Postvisual and Personal. There are no runtime or build dependencies outside Node's standard library. Keep the shared CSS below 32 KB uncompressed; report gzip size when changing it. This includes common selection, playhead, composed-field and scaled-action roles replacing duplicated app CSS. Delete superseded app paint and shared rules rather than adding compatibility overrides; mark only the bundled UI sheet for replacement.

Edit src, then run npm run check. The build validates inputs before replacing working assets and writes the update manifest last. public is generated deployment output, including synthetic catalogue media. Never copy private application source, client media, credentials, or data into this public repository.

Shared control paint, focus, density and prose belong in src/controls.css. The two palettes belong in src/tokens.json. Catalogue CSS uses @layer app and semantic tokens for layout. Never invent a third page palette or independent button implementation. Output-only creative rendering is outside this system.

Keep native HTML behavior. Optional JS must support keyboard use, release listeners and timers, stop background work in hidden views, and avoid app state. CSS refresh must preserve inputs, focus, open overlays and media state. Runtime behavior changes are bundled releases; the automatic channel carries CSS only.

For UI behavior changes, verify the actual browser, including mobile, both packs, keyboard controls and more than one open view. Keep the managed host a one-way deployment from the dev source. Do not touch unrelated LaunchAgents or Tailscale Serve routes.

Use documented shared native DOM patterns for controls. Compose actions with `.ui-actions`/`.ui-toolbar`, SVG `.ui-icon` + `.ui-label`, native `.ui-field` inputs/selects, `.ui-group` and `.ui-disclosure`; do not create app-specific replacements. Add a missing reusable pattern here and demonstrate it in the catalogue before app adoption. Keep links in one-line native fields with copy actions, use `.ui-truncate` for compact filenames, and keep selectors within the same field border as their label. Dynamic labels use `SharedUI.setActionLabel` so icons and accessible names survive.

For a record or inspector, render its ordinary facts as visible native `<section class="ui-stack">` blocks with `.ui-section-title` headings. Put a direct link beside a document or source; show large originals in their own view. A disclosure is for optional controls or a drill-down on an individual row, not a substitute for a record section. Do not make a vertical run of disclosure buttons from the sections of one record, or nest read-only section disclosures. If secondary facts truly need collapsing, group them under one Details control and use plain headings inside. Check the full view at phone width before shipping.

Both packs expose the same component types, subtypes, DOM and behavior. Make appearance changes through shared semantic component tokens. Horizontal action groups compact captions together, including primary actions; an explicit always-visible caption keeps its whole group readable. Headers align commands to the end by default. Remove redundant helper prose from operational menus and controls; retain text only when it helps someone make a decision or recover from an error. Retire superseded markup, handlers and styles in the same change.
